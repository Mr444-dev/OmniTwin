# Swarm planning and isolated policy execution

`OmniTwin.Policies` contains `PerimeterPatrolPolicy`, `HazardQuarantinePolicy`, `GridSearchAndRescuePolicy`, and `EmergencyHoldPolicy`. Policies use actual telemetry and footprints, deterministic ordering, a 0.55 m clearance disc, swept-segment collision checks and bounded A* next waypoints. Grid search advances only after measured arrival on a new telemetry sequence. Quarantine chooses the largest designated hazard, then the largest obstacle, with ID tie-breaking. Unreachable destinations hold safely.

The Unity scene contains three `AGV_GROUND` NavMesh agents and two `DRONE_AERIAL` controllers. Their actual transforms/velocities and simulated battery consumption are reported at 10 Hz through an asynchronous local HTTP client. `LineRenderer` displays paths. Ground agents use the baked floor NavMesh, obstacle carving and a local physics guard while carving catches up. Aerial altitude is handled separately; planar paths still avoid observed footprints. These are simulated agents, not physical robot control or measured battery hardware.

Backend controls correlate telemetry session/sequence, perception stream and calibration. Unity also checks its latest WebSocket observation and swept segments before applying movement. A control reply expires after 750 ms; failed perception, a stale stream, local tracking loss or a camera heartbeat older than one second causes immediate zero-speed Hold. Retaining a stationary verified obstacle for 20 seconds does not bypass these gates.

## Baseten and self-repair

Set `BASETEN_API_KEY` only in the backend terminal using the [masked key guide](api-keys.md). The real endpoint is `https://inference.baseten.co/v1/chat/completions`, with Bearer authentication. It starts with `meta-models/muse-spark-open-1026`. Only its HTTP 404 authorizes switching to `meta-models/muse-spark-open`. The resolved alias remains in use for that client's subsequent repair requests. HTTP 401/403/429 never triggers a model substitution. HUD/status report the actual attempted ID and fallback flag.

Each generation operation allows three transient HTTP attempts with exponential backoff, `Retry-After`, 15-second attempt and 45-second total deadlines. The one authorized 404 alias retry is additional to the transient failure budget. Retried requests can incur additional provider cost. Headers/bodies are bounded; raw response/error bodies and tokens are not logged. Cancellation and superseding commands stop generation. A bounded latest-command queue prevents backlog; baseline/Hold commands also cancel synthesis.

Muse returns locally validated JSON with exactly `policySource` and `decisionSummary`. No unsupported provider JSON-mode feature is requested. The summary is public output, not hidden reasoning. At most three **total** generation/compile attempts run; repair requests include the previous complete source together with bounded compiler diagnostics. The combined context is capped at 60,000 characters and fails explicitly when too large. A baseline continues during synthesis. Missing keys, invalid output, rejected candidates or execution faults produce safe fallback categories.

The provider adapter follows [Baseten Model APIs](https://docs.baseten.co/inference/model-apis/overview); public model examples use the undated alias. The dated variant's availability and live account permissions remain unverified. Local HTTP protocol fixtures prove request/response/error handling, not access to hosted weights.

## Compilation and OS boundary

`RoslynPolicyCompiler` uses Microsoft.CodeAnalysis.CSharp 5.9.0, a 65,536-character source cap, 20,000-node/128-depth limits and a five-second cooperative compilation deadline. Exactly one public sealed `ISwarmPolicy` class is permitted. Syntax restrictions and `SemanticModel` verify actual types/members against explicit primitives, math, generic collections, LINQ and contract types. Reflection/GetType, dynamic/native/unsafe/attribute capabilities and external I/O are rejected. Successful emission requires zero compiler errors and warnings. The backend receives owned image bytes; it never loads or instantiates generated types.

`WindowsPolicySandbox` copies trusted worker binaries and the image into an owned `local/policy-sandbox/<unique-profile>` directory, grants that AppContainer read/execute access, and launches the installed `Program Files/dotnet/dotnet.exe` using native security capabilities and an explicit three-handle IPC inheritance list. The environment is rebuilt from required OS/runtime paths; neither API key is inherited. Generated code loads only after the worker checks `TokenIsAppContainer`.

The AppContainer has **zero capabilities**, including network capabilities. A Job Object limits active processes to one, committed process/job memory to 256/384 MiB and process CPU time to 30 seconds; kill-on-close is enabled. The managed heap is capped at 128 MiB. Startup/constructors/JIT and trusted serializer metadata preparation share eight seconds. Every compute has a **100 ms wall deadline** that terminates the entire job; OS scheduling can delay timeout delivery. Worker lifetime is ten minutes, after which the next request selects a built-in fallback. IPC is length-prefixed with a 64 KiB allocation cap, not unbounded line reads. Cleanup is restricted to the exact owned sandbox child path. Build and publish both deploy the trusted worker in `PolicyWorker/`; a missing deployment fails before paid generation begins.

The host validates exact agent coverage, unique IDs, finite vectors and speed ≤4 m/s, clamps targets to workspace bounds, checks the calibrated polygon and collision-safe next segments. Invalid/nonfinite output never reaches Unity. The trusted worker may read publicly accessible Windows/runtime files and its own AppContainer profile; the boundary is not a claim that every filesystem path is inaccessible. This implementation targets Windows desktop; other OSes fail closed with `os_isolation_unavailable`.

Tests run an actual AppContainer token/file/loopback/no-keys probe. A real listener accepts a host control connection and receives no sandbox connection; Windows may reject directly or silently block until the probe deadline. Other tests run actual compiled policies, infinite loops, allocation pressure, constructor faults and nonfinite vectors. See [verification](verification.md). The design follows Microsoft's [AppContainer launch](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer), [process attributes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute) and [Job Object limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information).
